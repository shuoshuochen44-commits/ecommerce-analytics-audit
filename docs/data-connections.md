# 数据连接、更新与边界

程序启动后显示空工作区。先进入“数据接入”，选择自己的文件、附带的独立订单文件或数据库，再预览和确认映射。页面没有默认经营数据或演示切换入口。

## 选择来源

上传支持 CSV、TSV、分隔 TXT、XLSX、BIFF8 XLS、XLSB、ODS、平面 JSON/JSONL/NDJSON、Parquet、SQLite、DuckDB。上传保存静态副本；若希望原文件修改后自动更新，请改用“监测本机文件”并选择本机路径。工作簿首行应是字段名，标题行或合并表头请先整理。

数据库先填写连接信息并读取可用表，再选择单个用户物理表。SQLite/DuckDB 已做真实本地读取与变化验证；MySQL/MariaDB、PostgreSQL、SQL Server、Oracle 驱动已打包，但尚无真实服务验收。密码只存在当前进程，重启后需重新填写。

## 确认映射

系统根据精确已知字段名建议九个角色，用户逐一确认：订单号、下单日期、省份、买家编号、商品分类、商品金额、运费、支付金额、订单状态。必须一行一笔完整订单，订单号不重复，一个汇总商品分类，金额为人民币非负数且最多两位小数。省份填写 31 个省级地区的完整名称。

订单状态支持已完成、已发货、处理中、已取消，也可从对应英文 delivered/shipped/processing/canceled 转换。日期写作 YYYY-MM-DD；原生日期值可转换。字符串标识符的前导零和 Decimal 精度保留；源数据若已将编号保存为数字，无法恢复丢失的前导零。

这不是通用业务建模或多表自动关联。多商品明细需先汇总，商品和支付多表需先按正确粒度整理；当前不会猜测连接关系。缺少真实交付日期或成本时，不推断物流时效或利润。

已确认的字段映射会保留。新来源只有在完整列名集合相同、历史方案唯一时才建议复用；列顺序可以不同，存在多个冲突方案时需重新选择。旧版配置升级后也可用于建议。界面显示建议来自当前来源、历史方案或已知字段名，仍需核对并确认订单口径。

“检查映射后数据”会检查整个选中表，返回行号、来源列、业务字段、原因与修改建议，不回显出错的个人编号或原始单元格值。最多展示 50 项，另显示实际总错误数；日期范围仅在检查通过时展示。CSV/TXT 使用记录起始物理行，工作簿使用实际工作表行号，JSONL 使用文本行号，均保留空行后的正确位置。JSON 数组、Parquet 和数据库按虚拟表格顺序编号（表头为 1，首条记录为 2）；数据库的读取行号不是稳定记录编号。映射、省略/重复字段、日期、省份、金额、订单状态、重复订单及输入限额均检查。修改映射/设置或重新预览后需重新检查，保存时与后台采集时也会核验，失败不覆盖已有成功版本。

## 刷新与版本

Windows 交付程序使用独立桌面窗口；文件选择和保存报告使用系统对话框，关闭窗口时停止自己的后台服务。重复启动恢复同一工作区窗口。升级会保留已有来源、快照和独立数据文件，不自动重置工作区。

手动刷新、10—3600 秒定时采集和 1—30 秒变更轮询共用同一流程。每次完整读取选定表，通过核验后才发布独立快照；内容不变不重复发布。每来源同一时刻仅一次采集，失败保留上次成功版本。成功后 SSE 通知页面，当前来源更新时保留筛选。

这是秒级轮询加 SSE，不是源数据库日志 CDC。轮询间隔不等于数据库提交到页面展示的实际延迟，当前没有端到端时效承诺。SQLite 已提交 WAL 更新可被读取；来源主文件 SHA 不足以识别所有变化，版本判断还比较采集后的规范化内容与映射。删除至空表也可更新为空快照，结构变化则需要重新确认映射。

来源配置与快照保存在工作区 `connections/`；每次成功生成 run_id 和来源证据。历史订单查询、导出与报告固定到选定的成功版本，不受之后源库修改影响。最多配置 16 个来源，成功版本持续保留，需要用户管理磁盘空间。

## 输入限额

- 文件大小最多 20 MB，表格展开后另有 20 MB 字节预算；最多 20,000 行、200 列，超限明确拒绝，不返回截断后的总量。
- 规范化九列 CSV 仍需满足既有 5 MB 导入限制。
- 工作簿最多 200 张表，ZIP 内部展开最多 80 MB/2,000 条目；工作簿维度与真实坐标在原生表解析前检查。BIFF8 之前的 XLS、加密文件请先转换。
- 嵌套 JSON、ZIP 多文件包、PDF/Word、图片 OCR、NoSQL 及其他未列出的格式尚未实现，需要先整理成已支持的平面表格。

本服务面向本机单用户，来源路径与数据库连接由该用户明确选择，不提供对外远程托管或任意 SQL 执行入口。

## 随附的五份订单文件

桌面交付位置为 `桌面交付目录/智数巡检`，已完成拷贝、哈希校验及空启动验证。目录包含 exe 和以下五个独立文件，每个均有相同的 12,000 行，可任选一种导入，无需五份全部导入：

| 文件 | 特点 |
|---|---|
| 订单数据.csv | UTF-8 BOM，九列中文表头 |
| 订单数据.xlsx | 单张 orders 工作表，无额外说明列/元数据工作表 |
| 订单数据.json | 平面记录数组，金额保持文本精度 |
| 订单数据.parquet | 金额为 DECIMAL(18,2) |
| 订单数据.sqlite | 单张 orders 物理表，九列中文字段 |

这些文件由独立脚本确定性构造，覆盖 2026 年 1—9 月、31 个省级地区、8 个分类和重复买家，不来自真实交易。程序不会自动导入它们，页面也不会插入模拟提示。

冻结 exe 五种格式实际导入后的四项结果一致：完成订单商品金额 3,891,488.72 元，完成订单数 10,843，商品金额客单价 358.89 元，去重购买客户数 6,776。该结果用于验证导入一致性，空工作区不会先显示这些数值。

开发环境可另行生成：

```powershell
.\.venv\Scripts\python.exe -B scripts/export_import_samples.py work/import-samples
```

脚本拒绝覆盖已有同名目标文件。输出短 JSON，包含五个文件路径、数量、币种与日期范围。
