# 离线可审计问答内核

用户已于 2026-10-18 选择“按此方案开发”：30 条预定义中文问题、受限 SQL、独立核验和运行记录。本阶段交付 Python 接口与命令行，复用已有不可变数据快照。后续再接模型、API 与页面。

## 起点与隔离

主项目位于 `历史源码目录`，已提交基线为 `3a68ede`。其 CSV 接入、查询与月份对比存在进行中的未提交文件。本阶段在当前工作区的 `work/auditable-analysis` 独立分支开发，仅复制已提交源码，不覆盖那些文件。独立基线 68 项测试通过。

## 方案选择

1. 离线模板闭环：可直接验证，零模型调用费用，推荐并已获用户选择。
2. 直接接模型：扩大中文表达能力，同时需要模型配置与生成质量评测，后续再做。
3. 先补 API 与页面：可演示交互，但仍缺少安全与核验内核，留待内核稳定后完成。

## 边界与数据流

固定中文问题/问题 ID + 筛选 → 目录精确匹配 → 绑定日期与地区参数 → SQLGlot AST 校验 → DuckDB 只读连接 → 独立原始层计算 → 质量影响判定 → 只写一次的分析清单。

- 30 条问题覆盖基础指标、时间趋势、维度排名、质量感知、口径查询和应拒答；问题目录不是通用自然语言理解。
- 金额按 Decimal 精确到分；币种来自快照元数据，保留模拟标记；完成状态和购买日期沿用既有口径。
- 本阶段不实现任意 CSV 上传、开放 SQL HTTP 入口、LLM Agent、论文对照实验、Docker 或视频，不把模板自测称为模型评测。
- 快照缺失、日期非法、地区未知、问题歧义均给可读原因，不退回“全部数据”计算。

## 安全执行

- 单条 SELECT/非递归 CTE；限制 SQL 长度、AST 节点、输出行数、参与源行数、时间、内存与线程。
- 用 AST 和作用域资格化校验表/列与允许函数；拒绝未知表列、DDL/DML、多语句、系统元数据、外部文件、表函数、递归和笛卡尔积。
- 外部访问和扩展自动安装/加载关闭；DuckDB 文件以 read_only 打开。源行数限额为执行前确定性预算，不宣称是精确物理扫描量估计。
- 超时包括执行与取数；超时不返回部分结果。所有计时器在关闭连接前取消并回收。

## 独立核验

SQL 查询模型层；核验器从原始文本表分别读取订单、商品、客户和支付，按订单粒度以 Python/Decimal 计算，对比返回的完整结果。不得把同一条 SQL 再运行一次作为核验。金额、排序、未知分组和唯一客户数具有显式规则。核验使用同一成功快照，不依赖 latest 指针后续变化。

质量警告按问题依赖的字段和规则关联。原始层复算一致只说明计算一致；仍受缺明细、缺客户等问题影响的回答标为 needs_review。核验不一致、无证据或运行失败为 blocked；只有计算和依赖证据均通过才为 verified。知识口径查询与拒答记录不假装进行 SQL 核验。

## 返回与审计

统一返回 answer、sql、parameters、result、chart_spec、citations、verification_status、quality_warnings、run_id，以及 snapshot_run_id、input_fingerprint、dataset、verification 和阶段日志。运行清单使用新 UUID，独占创建文件；不能覆盖已有记录。保存问题 ID、模板/内核版本、数据输入哈希、实际 SQL/参数、聚合结果和耗时，不保存原始客户标识或自由输入全文。

同一快照、问题和筛选可重放并比较业务结果；运行 ID 与时延不要求相同。记录中区分源数据快照 ID 与分析运行 ID。

## 验收

- 30 条目录问题均有明确回答/拒答与可读口径；人工小样本金标准覆盖每种可计算问题。
- 写入、多语句、外部读取、未知表列、危险函数、递归、预算、行数、超时均有拒绝测试；拒绝后数据库未改变。
- 注入计算差异必须 blocked；缺客户/商品等规则对相应问题为 needs_review，其他指标不被泛化阻止。
- 所有回答有固定快照证据、运行清单；运行记录可读取并重放，失败不会发布数据或破坏旧快照。
- 既有 68 项测试继续通过；输出逐问题的本地模板验收 JSON，明确未连接模型、没有比较模型效果。
