# 桌面问答与导入体验优化

用户已同意按上一轮建议推进，首轮聚焦问答界面与导入体验；继续使用当前开发副本和桌面交付，不更改用户已有数据。

## 问数据

在现有桌面导航增加“问数据”，提供全部 30 条预定义问题、分类、目录内文本输入与问题快捷按钮。沿用确定性分析内核，不引入模型或任意 SQL。问答固定到提交时实际显示的数据源、成功快照、月份与地区；新版本到来时提示可重新分析，已展示回答继续保留原版本证据。

结果先展示结论与核验状态，再展示聚合表格/图形和相关质量提示；展开可见实际 SQL、参数、指标口径、来源指纹、快照和分析运行编号。拒答/核验失败不展示可用于业务结论的数字。支持下载完整 JSON 记录和重放当前运行。切换数据源或筛选后明确标识旧回答范围，防止混淆。

本机 HTTP 接口包含问题目录、提交分析、读取运行、重放运行。复用来源选择与同源提交限制，限制请求大小、字段、并发，始终按给定快照读取。运行路径不允许任意文件访问。

## 导入

复用当前来源已保存的映射；新来源列名集合相同且历史映射唯一时建议复用，多个历史方案冲突时不猜测。建议必须由用户确认，不自动发布。

增加独立的“检查映射后数据”步骤，检查完整选中表，返回行号、原字段、业务字段、错误原因和修改建议，最多列出 50 项并明确是否省略更多错误。不返回原始个人编号或整行数据。保存/刷新同样执行完整校验，不绕过检查。CSV、工作簿与 JSONL 保留真实来源行号（含空行），其他表格按虚拟表头为 1 的记录顺序编号；避免过滤空行或排序导致提示错行。

界面标明建议来源、映射完成数量，重复选择列时提示；检查成功显示总行数和日期范围。配置更改后旧检查结果失效，采集失败可展示受控的行列提示，失败不覆盖上次成功快照。保持金额和业务口径严格，不自动猜测退款、货币或粒度。

## 验收

HTTP 测试覆盖快照固定、来源隔离、筛选、拒答、同源、重放和非法输入；导入测试覆盖复用冲突、多个错误、行号、失败保留和旧配置兼容。全套回归通过后打包，用独立测试工作区实际打开原生窗口验收，再只更新桌面 exe，保留工作区及五份数据文件。
