# 本地经营分析与质量监控 MVP

用户已取消按周推进，要求共同连续工作到可见的大结果。当前交付目标为本机可用的完整数据产品，直接在本会话实施。

## 方案

原始 CSV → 五张 raw 表 → 五张明细/维度表 → 日期地区汇总 → 只读网页和可复现报告。Python 和 DuckDB 负责加工、检查、日志与查询；标准库 HTTP 服务和本地 HTML/CSS/JS 提供中文页面，无额外前端依赖。

优先实体明细表而非单张宽表，商品和支付分别汇总到订单再关联，避免放大金额。订单、商品行、客户映射、商品和订单支付分别具有明确唯一键。原始字段保持文本，金额采用 DECIMAL(18,2)，时间使用 TIMESTAMP。孤儿记录保留并计数，非法金额或日期以及重复关键键阻止发布。

## 质量与发布

实施八条必做规则：订单主键非空/唯一、商品行键唯一、商品行订单存在、商品行商品存在、订单客户存在、商品金额非空可解析非负、购买日期非空可解析。附加客户/商品键、运费、支付、状态与时间检查，规则记录失败数、比例、样例键、严重级别及指标影响。关系孤儿展示警告；破坏粒度或类型的错误阻止发布。支付差异单独报告，不自动改源数据。

每次执行生成独立 run_id、输入 SHA256、版本、数量、规则结果和独立数据库。加工与原始层 SQL 四项指标对照通过后，以原子替换 latest.json 发布整批结果。失败保存日志，旧 latest 不变。输入处理前后哈希必须相同。页面逐请求读取一个完整成功批次。

## 页面

经营概览：四张 KPI、按月趋势、州与品类排名、日期范围和州筛选；客户数在筛选后的订单上独立去重，不加总地区/月份去重数。金额不含运费且只计已交付订单，以购买日期归属；空分母显示空值。趋势提示边界月份覆盖限制，不默认计算完整月环比。

质量报告：全批次规则结果、对账统计、异常样例、运行版本与输入证据。明确质量结果不随经营筛选变化。网页仅提供固定查询、参数绑定、只读访问，无任意 SQL 执行入口。监听 127.0.0.1。

## 验收

- 小样本、金额放大、缺商品已交付订单、重复客户、非法金额、孤儿记录、空筛选、非法筛选和批次失败恢复有自动验证。
- 真实数据四项指标与已有基线一致；日期/地区/品类金额与总体对齐。
- 重复运行结果相同，快照状态修改反映到历史聚合；失败不污染已发布结果。
- 本地 HTTP 可访问，筛选和页面呈现经过实际浏览器检查；报告说明业务发现与限制。
- 提供一键加工/启动命令、测试、模型说明、输入证据和中文操作交付。
