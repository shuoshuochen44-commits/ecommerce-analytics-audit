# 统一数据接入与在线刷新：已确认范围与当前实现

更新：2026-10-18。本文件原为范围草案，现按已实现能力及最新用户要求更新。原先的“默认加载演示数据”要求已被替换：程序启动为空，由用户自行导入或连接；页面不出现模拟提示。独立示例文件已随 exe 放入 `桌面交付目录/智数巡检`，六个文件哈希一致，默认端口空启动与重复启动复用均已验证。

## 产品流程

空工作区 → 数据接入 → 上传文件/监测本机文件/连接数据库 → 选择工作表或物理表 → 预览字段与少量记录 → 确认九列订单映射及人民币口径 → 采集、质量检查、成功发布 → 看板、订单查询/导出与报告。

文件头可生成字段建议，建议不代替确认。一行必须代表一笔完整订单；九个字段为订单号、下单日期、省份、买家编号、商品分类、商品金额、运费、支付金额、订单状态。当前不实现多表关系推断或自动业务语义映射。离线问答内核继续通过 CLI 对固定成功批次工作，尚未接入看板或大模型。

## 文件能力与限制

| 已实现类型 | 当前约束 |
|---|---|
| CSV、TSV、分隔 TXT | UTF-8/BOM/GB18030；TXT 使用逗号、制表符、分号或竖线；首行明确且不重复的表头 |
| XLSX、BIFF8 XLS、XLSB、ODS | 首行为表头；枚举有效工作表，不执行宏；坐标与展开限额预检查；旧于 BIFF8 的 XLS、加密/损坏工作簿拒绝，建议转换 |
| JSON、JSONL/NDJSON | 对象数组或明确的 `{records:[...]}`；字段一致，保留 Decimal；嵌套对象/数组拒绝并要求先展开 |
| Parquet | 有界 DuckDB 读取；保留 Decimal、日期与字符串标识符；嵌套字段不进入当前平面模型 |
| SQLite、DuckDB 文件 | 只读用户物理表；排除视图、系统对象与 SQLite FTS 影子表；不执行文件附带脚本 |

文件源最多 20 MB，展开后的表格数据另有 20 MB 字节预算，最多 20,000 行、200 列；超限拒绝，不能截断后显示总量。转换后的规范化订单 CSV 另受既有 5 MB 限制。工作簿 ZIP 展开最多 80 MB/2,000 个条目；二进制维度与实际单元格坐标在原生表格解析前检查。这是有界格式兼容，不是对任意恶意二进制文件的全面安全证明。

**未实现**：ZIP 多文件导入、任意 JSON 路径选择/展开、PDF/Word 提表、图片 OCR、XML/HTML/ORC/Avro 等额外类型。此类输入需要先转换成已支持的平面表格。

## 数据库能力与实测范围

| 类型 | 状态 |
|---|---|
| SQLite、DuckDB | 已真实本地读取和变化回归；选择单一用户物理表，保留读取事务/快照边界 |
| MySQL/MariaDB、PostgreSQL、SQL Server、Oracle | 已有适配代码，驱动纳入打包；没有真实服务器连接与故障场景验收，不标作已实测 |
| ClickHouse/Trino/Snowflake 等其他 SQL 引擎 | 未适配；不能因 SQLAlchemy 提供某种方言而宣称产品支持 |
| MongoDB/Elasticsearch/Redis 等 NoSQL | 未适配，尚无读取、展开及语义映射 |

连接字段固定，拒绝任意用户 SQL、DSN 附加选项与扩展加载。使用符合采集要求的权限账号；只读事务、超时与取消能力按具体数据库区分。SQL Server 适配使用可串行化事务并回滚，未宣称服务器强制只读。不存在跨表一致性或跨源联合快照保证。

## 刷新语义

- **手动**：点击刷新后完整读取选定表，核验成功才发布新快照。
- **定时**：10—3600 秒间隔，复用同一采集过程。
- **变更监测**：1—30 秒轮询可监测的本机文件/选定数据库表，比较采集后的内容及来源映射，变化后发布，再用 SSE 通知页面。秒级描述轮询间隔，不代表测得的端到端延迟。

当前是全量采集与内容比较，**不是日志 CDC**。上传副本不跟踪原文件，原文件变化需要配置本机路径来源。新增、修改、删除通过完整选定表内容反映；删除至空表可生成合法空快照。每个来源同一时间只有一次采集，忙碌时合并触发，不累积重叠执行。页面显示最后检查/成功状态，失败继续保留旧成功版本。当前没有通用端到端延迟指标或时效 SLA。

## 版本、凭据与证据

来源配置、表选择和人工映射保存在工作区，最多 16 个来源。密码仅保存在本次进程内存，不写入配置/清单，重启后重新输入；没有宣称已接入系统密钥库。原始错误不会把连接凭据或文件内容回显给页面。

规范化订单数据、来源元数据和映射共同参与版本指纹；成功批次有独立 run_id、源 CSV 与来源证据。文件 SHA 是主文件证据，不代表 SQLite WAL 状态；WAL 已提交变化通过只读表采集与内容比较捕获。失败不覆盖成功批次，模式漂移需要重新预览确认。当前缺少真实交付日期，不能推断物流时效；缺少成本不能计算利润。

## 独立文件与交付验收

`scripts/export_import_samples.py` 确定性生成相同的 12,000 笔完整订单，导出 `订单数据.csv/.xlsx/.json/.parquet/.sqlite`。覆盖 31 个省级地区、8 个商品分类、2026 年 1—9 月、重复买家及三种状态，金额为人民币且保持精度；文件独立存放，不在启动时自动读取。它们是构造样本，不是实际交易资料。

冻结 exe 已实际导入五种格式，四项结果一致：完成订单商品金额 **3,891,488.72 元**、完成订单数 **10,843**、商品金额客单价 **358.89 元**、去重购买客户数 **6,776**。最终全套自动化回归 **325 项通过**；桌面 exe 和五个独立文件已完成拷贝与空启动验证。

本轮没有完成清空依赖后的新环境重装验收，没有真实网络数据库服务验收，也没有可推广的端到端延迟测量。最终交付记录应保留这些边界，不能把计划项改写为已完成证据。
