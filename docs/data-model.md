# 数据模型与指标字典

当前以可运行里程碑推进，不再按周划分开发任务。历史按周文档保留为早期基线证据。

## 数据流

原始 CSV → raw_* 文本表 → 质量断言 → 明细/维度 → 日期地区汇总与全局指标视图 → 原始层独立核对 → 发布整批只读快照 → 网页与 Markdown 报告。

| 对象 | 一行的含义 | 唯一业务键 | 主要字段 |
|---|---|---|---|
| dim_customer_mapping | 一条订单客户身份映射 | customer_id | customer_unique_id、城市、州、文本邮编 |
| dim_products | 一个商品 | product_id | 源品类名称，缺失不推断 |
| dwd_order_items | 一条订单商品行 | order_id + order_item_id | price、freight_value、商品/订单缺失标记 |
| dwd_order_payments | 一个订单的支付汇总 | order_id | payment_count、payment_amount |
| dwd_orders | 一个源订单 | order_id | 状态、日期、稳定客户、州、商品及支付合计、对账状态 |
| dws_daily_state | 一个购买日期和客户所在州 | purchase_date + customer_state | 已交付订单商品金额、订单数 |
| ads_overview | 整个快照的四个核心指标 | 单行 | 金额、订单数、客单价、唯一客户数 |

客户表的 customer_id 为订单级身份映射，customer_unique_id 才是重复购买客户识别字段。去重前去除首尾空白，空值不计入客户数并报告警告。

## 四项指标（1.0）

统一筛选：order_status = delivered，以 purchase_date 归属当前快照的最终状态。币种 BRL。

| 指标 | 定义 | 空值/分组规则 |
|---|---|---|
| 完成订单商品金额 | 已交付订单商品价格 sum(price)，不含运费 | 无可用金额时为空；DECIMAL(18,2) |
| 完成订单数 | 已交付源订单唯一键数 | 无商品明细仍计入 |
| 商品金额客单价 | 完成订单商品金额 ÷ 完成订单数 | 分母为零返回空值；结果两位小数 |
| 唯一购买客户数 | 当前筛选范围内稳定客户标识去重数 | 不可加总月份或州去重数；缺标识另报 |

品类金额按商品行求和；跨品类订单数不可相加。无品类或孤儿商品归到“未知品类”，不静默丢弃。空地区单独可筛选。

## 质量与对账

quality.py 中每条规则记录版本、表、失败记录数/比例、样例键、指标影响和发布策略。Q01/02/03/04/05/06/07/10 为八条核心规则；其余检查维度键、运费、状态、支付键、稳定客户、交付日期和支付关联。

重复键、无效金额/购买日期和不合法状态阻止发布。商品和支付序号必须为规范正整数字符串，防止 01 与 1 绕过业务键检测。金额须精确到分、非负且可解析；不通过静默舍入掩盖异常。孤儿关联、缺稳定客户、交付日期问题保留并展示警告。规则失败记录数可能互相重叠。

支付对账以所有源订单为范围，商品与支付各自先聚合，比较商品金额 + 运费与支付总额，容差 0.01。缺明细、缺支付、两者都缺和金额不一致分别标记。没有源订单的商品/支付记录保留在原始层/明细层，单独统计，不伪造源订单。

## 快照与发布

每次运行在 artifacts/analytics/runs/run_id 中建立独立 DuckDB、规则 JSON、指标 JSON、运行清单和报告。输入文件处理前后 SHA256 必须一致；四项明细指标与原始 SQL 基线一致。所有步骤通过后才原子替换 latest.json。

失败批次保留 manifest.json 和已产生的质量证据，旧成功快照继续可读。历史成功数据库不被覆盖。此实现为全量快照重建，暂不做增量计算或长期批次清理。

看板后端逐请求选定一个成功批次，以只读连接执行固定模板，日期/州使用绑定参数。只监听本机 127.0.0.1，没有任意 SQL 入口。网页质量与下载报告均为全批次范围，经营图表随筛选变化。
